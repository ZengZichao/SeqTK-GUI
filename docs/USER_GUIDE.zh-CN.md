## 开始之前

如果你拿到的是打包好的 **`SeqTK-GUI.exe`**，无需安装任何东西：seqtk 程序就在这个文件里，
首次启动会花几秒把自身解压到临时目录。

界面需要一个 seqtk 可执行文件，按以下顺序查找，结果显示在右下角状态栏：

1. 你在 **工具 > 指定 seqtk 程序…** 中保存的路径；
2. 随程序一起分发的 `bin/windows/seqtk.exe`——源码运行时在项目目录内，打包版则由
   PyInstaller 解压到临时目录后自动找到；
3. `PATH` 中的 `seqtk`。

选项列表依据 seqtk 1.5-r133 编写。若你使用的程序报告了别的版本，状态栏会提示；
仍可运行，但选项可能与界面上列出的不完全一致。

## 窗口布局

| 区域 | 作用 |
| --- | --- |
| 左上 | 搜索框，可匹配命令名与上游帮助文字 |
| 左列表 | 全部 24 个子命令，分为通用处理 / 区域分析 / 未公开列出 |
| 右上 | 所选子命令的参数表单：先输入项，再选项 |
| 右下 | 标签页：**标准输出**、**标准错误 / 日志**、**命令行**；标签页下方有**清空输出**与**复制当前页**按钮 |
| 底部 | **将标准输出写入文件** + 路径、**运行**、**停止** |
| 状态栏 | 左侧为上次运行结果，右侧为 seqtk 路径与版本 |

拖动表单与输出之间的分隔线可调整比例；把 FASTA/FASTQ 文件拖到窗口任意位置，会
自动填入第一个文件输入框。

## 选择子命令

分组方式与上游帮助输出一致：

* **通用处理** - `seq`、`size`、`comp`、`sample`、`subseq`、`fqchk`、`mergepe`、
  `split`、`trimfq`
* **区域分析** - `hety`、`gc`、`mutfa`、`mergefa`、`famask`、`dropse`、`rename`、
  `randbase`、`cutN`、`gap`、`listhet`、`hpc`、`telo`
* **未公开列出** - `hrun`、`kfreq`：`main()` 可以调用，但 `seqtk` 帮助里没有。
  用法与其他命令相同，界面特意标注来源。

表单顶部会重复上游的 usage 行，方便你在终端里用 `seqtk <命令>` 对照。

## 填写参数

**输入**是 seqtk 的位置参数，顺序与 seqtk 读取的顺序一致。带 `*` 的为必填。
可点 `…` 选择文件，也可直接粘贴路径。`split` 的前缀字段选择目录后自动补上前缀名，
seqtk 会写出 `<prefix>.00001.fa`、`<prefix>.00002.fa` 等文件。

**选项**分两种：

* 单个复选框，例如 `-r`：勾选即传入该开关；
* 复选框 + 取值控件，例如 `-l 60`：只有勾选后取值控件才可用。

未勾选的选项**完全不会**传给 seqtk，因此由 seqtk 自己的默认值决定行为。字段旁
显示的数字是上游默认值，控件初始也停在那里，但不勾选就不会出现在命令里。这样
生成的命令与你手敲的完全等价。

数值范围按 seqtk 能接受的上限设置：`-Q`（质量偏移）最大 126，`-X` 最大 255，
依此类推；`-q`/`-f` 支持小数。

**命令行**标签页随输入实时更新，可用 **编辑 > 复制命令行** 复制，便于在终端复用
或留档。

## 运行

点击 **运行** 或按 Ctrl+R。执行是异步的：窗口不卡死，输出边产生边显示，**停止**
会结束子进程。进程退出后状态栏显示退出码与耗时；退出码非零时自动切到日志页。

seqtk 自己的信息（`[W::stk_seq] …`、`[E::stk_seq] failed to open the input
file/stream.`）只会进入日志页，不会混进结果页，因此结果页可以直接复制使用。

## 查看结果与错误

* **标准输出** - 命令的真实输出。序列类命令是 FASTA/FASTQ 文本；`size`、`comp`、
  `fqchk`、`gap`、`gc`、`telo`、`hrun`、`kfreq` 是表格。
* **标准错误 / 日志** - seqtk 的告警与报错，以及界面附加的信息（例如输出文件大小）。
* **命令行** - 实际执行的完整调用，已按当前系统的引号规则转义。

有些命令本来就可能不输出任何内容（没有足够长的 `gap`、不满足阈值的 `gc`、得分
不够的 `telo`）。结果页为空并不等于失败，请结合状态栏的退出码判断。

## 处理大输出

标准输出页最多显示 200,000 字符以保证界面流畅，超出后会明确提示并停止追加。
真正处理大数据时请勾选 **将标准输出写入文件** 并给出路径：界面会把文件句柄直接
交给子进程，效果等同命令行的 `>`，几 GB 数据也不会进入内存。此时结果页为空是
预期行为。

覆盖已存在的文件会二次确认。`split` 自己写文件、不使用标准输出目标，可用
**文件 > 设置工作目录…** 控制它的输出位置。

## 语言与主题

**视图 > 语言** 可在简体中文与 English 之间立即切换：菜单、命令列表、表单标签、
提示、校验信息、关于对话框都会同步变化，无需重启。选项说明是上游措辞的译文，
选项字母与默认值保持原样。

**视图 > 主题** 可在明亮与黑暗之间切换。两者都由调色板加少量样式表实现，在
Windows 与其他平台的 Qt 风格下表现一致。

选择会按用户保存。

## 各子命令要点

首次使用前值得了解（完整清单见 [COMMANDS.zh-CN.md](COMMANDS.zh-CN.md)）：

* `seq -A` 与 `seq -a` 在上游是同一个开关，界面统一提供 `-A`。
* `seq -n 0` 的含义是“遮蔽为小写”，而不是“替换成字符 0”。
* `seq -M` 需要 BED 或名称列表；配合 `-c` 可改为遮蔽补集区域。
* 双端数据用 `sample` 抽样时，两个文件必须使用相同的 `-s` 种子才能保持配对。
* `trimfq` 的 `-b`、`-e`、`-L` 一旦非零，上游会忽略 `-q` 与 `-l`；这是 seqtk 自身
  的优先级，界面不做额外屏蔽。
* `trimfq -Q` 出现在上游帮助文本中，但其 `getopt()` 并不接受，因此界面不提供。
* `mergefa` 的 `-m` 与 `-i` 不能同时使用，seqtk 会报错退出。
* `telo` 的 BED 结果走标准输出，`(端粒碱基数, 输入碱基数)` 汇总走标准错误；
  想检出较短的端粒就调小 `-s`。
* `kfreq` 会用断言要求 k-mer 只含 A/C/G/T，否则进程中止；界面在启动前做同样校验。

## 常见问题

**状态栏提示未找到 seqtk。** 用 **工具 > 指定 seqtk 程序…** 手动指定，或把 seqtk
加入 `PATH`。

**状态栏提示版本不一致。** 仓库自带的程序报告 1.5-r133。换成其他版本时，选项的
数量与含义可能变化，请以该版本自身的帮助文本为准。

**退出码为 0 但结果页为空。** 对“确实没有命中”的命令属于正常；`split` 只写文件，
本来就没有标准输出。

**输出显示到一半停止。** 触发了 200,000 字符的预览上限，请改用“将标准输出写入文件”。

**日志里出现乱码。** seqtk 只输出 ASCII，异常字符来自你的输入文件本身；界面的
解码方式是 UTF-8 加替换，不会中断读取。

**在没有中文字体的服务器上一片方框。** 到 **视图 > 语言** 切到 English，或安装
CJK 字体。
