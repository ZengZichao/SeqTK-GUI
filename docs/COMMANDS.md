# seqtk 1.5-r133 subcommands

Every subcommand and option exposed by the GUI, transcribed from `seqtk.c` of upstream seqtk 1.5-r133. Generated by `scripts/generate_commands_doc.py`; do not edit by hand.

## General processing

### `seq`

common transformation of FASTA/Q.

```text
seqtk seq [options] <in.fq>|<in.fa>
```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-q` | int | `0` | mask bases with quality lower than INT [0] |
| `-X` | int | `255` | mask bases with quality higher than INT [255] |
| `-n` | char | `unset` | masked bases converted to CHAR; leave unset to lowercase |
| `-l` | int | `0` | number of residues per line; 0 for 2^32-1 [0] |
| `-Q` | int | `33` | quality shift: ASCII-INT gives base quality [33] |
| `-s` | int | `11` | random seed (effective with -f) [11] |
| `-f` | float | `1.0` | sample FLOAT fraction of sequences [1] |
| `-M` | file | `unset` | mask regions in BED or name list FILE [null] |
| `-L` | int | `0` | drop sequences with length shorter than INT [0] |
| `-F` | char | `unset` | fake FASTQ quality [unset] |
| `-c` | flag | `off` | mask complement region (effective with -M) |
| `-r` | flag | `off` | reverse complement |
| `-R` | flag | `off` | output both forward and reverse complement |
| `-A` | flag | `off` | force FASTA output (discard quality)  (-a is a synonym) |
| `-C` | flag | `off` | drop comments at the header lines |
| `-N` | flag | `off` | drop sequences containing ambiguous bases |
| `-1` | flag | `off` | output the 2n-1 reads only |
| `-2` | flag | `off` | output the 2n reads only |
| `-V` | flag | `off` | shift quality by '(-Q) - 33' |
| `-U` | flag | `off` | convert all bases to uppercases |
| `-x` | flag | `off` | convert all lowercases to -n |
| `-S` | flag | `off` | strip of white spaces in sequences |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input` | `seq_file` | required | <in.fq>\|<in.fa> |

**Notes**: stk_seq's getopt string accepts '-a' and routes it to the same case as '-A', while the usage text never lists '-a'; the GUI exposes '-A'. seqtk accepts a lone '-' to read stdin, but the GUI always passes a file path. The usage text of stk_seq describes '-n CHAR' as '0 for lowercase [0]', which the code contradicts: mask_chr is initialised to the integer 0 (the NUL character) and is only used as the mask when it is non-zero, otherwise the masked base is lowercased. Passing '-n 0' therefore writes the digit 0 into the sequence, so this spec gives -n no default and leaves the option out until the user types a character. '-x' likewise only rewrites lowercase bases when -n supplies a non-zero character.

```text
seqtk comp [options] <in.fa>|<in.fq>
```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-u` | flag | `off` | only count uppercased bases |
| `-r` | file | `unset` | restrict counts to regions in BED FILE |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input` | `seq_file` | required | <in.fa>\|<in.fq> |

**Notes**: Output columns: chr, length, #A, #C, #G, #T, #2, #3, #4, #CpG, #tv, #ts, #CpG-ts. With -r each row describes one BED region rather than one sequence and starts with chr, beg and end, giving fourteen columns; the upstream usage text only documents the layout without -r.

### `sample`

subsample sequences.

```text
seqtk sample [options] <in.fa>|<in.fq> <frac>|<number>  values >= 1 are read counts, below 1 are fractions
```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-2` | flag | `off` | 2-pass mode: twice as slow but with much reduced memory |
| `-s` | int | `11` | RNG seed [11] |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input` | `seq_file` | required | <in.fa>\|<in.fq> |
| `number` | `number` | required | <frac>\|<number>  values >= 1 are read counts, below 1 are fractions |

**Notes**: For paired-end data sample both files with the same -s seed to keep pairs together. -2 only applies to a whole-number argument: with a fraction stk_sample keeps the one-pass path and ignores the flag, and two-pass mode refuses to read stdin.

### `trimfq`

trim FASTQ using the Phred algorithm.

```text
seqtk trimfq [options] <in.fq>|<in.fa>
```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-q` | float | `0.05` | error rate threshold (disabled by -b/-e) [0.05] |
| `-l` | int | `30` | maximally trim down to INT bp (disabled by -b/-e) [30] |
| `-b` | int | `0` | trim INT bp from left (non-zero to disable -q/-l) [0] |
| `-e` | int | `0` | trim INT bp from right (non-zero to disable -q/-l) [0] |
| `-L` | int | `-1` | retain at most INT bp from the 5'-end; only a value > 0 takes effect and it then disables -q/-l [-1] |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input` | `seq_file` | required | <in.fq>\|<in.fa> |

**Notes**: Upstream usage text lists '-Q  force FASTQ output', but the getopt string of stk_trimfq ("l:q:b:e:L:") does not accept it, so the option is not exposed here. The usage text also prints '-L INT ... [0]' while the handler initialises fixed_len to -1; the code tests fixed_len > 0, so -1 and 0 behave alike and the default recorded here follows the code.

### `mergefa`

```text

```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-q` | int | `0` | quality threshold [0] |
| `-i` | flag | `off` | take intersection |
| `-m` | flag | `off` | convert to lowercase when one of the input base is N |
| `-r` | flag | `off` | pick a random allele from het |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input1` | `seq_file` | required | <in1.fa> |
| `input2` | `seq_file` | required | <in2.fa> |

**Notes**: The merged sequences go to stdout; the (same,diff,hom-het,het-hom,het-het) counters go to stderr. -m and -i cannot be applied at the same time: stk_mergefa tests is_mask && is_intersect and exits, but the message it prints names '-h' instead of '-m', so trust the condition in the code rather than the wording of the error.

### `telo`

identify telomere repeats in asm or long reads.

```text
seqtk telo [options] <in.fa>|<in.fq>
```

**Options**

| Flag | value | default | Meaning |
| --- | --- | --- | --- |
| `-m` | string | `CCCTAA` | motif [CCCTAA] |
| `-p` | int | `1` | penalty [1] |
| `-d` | int | `2000` | max drop [2000] |
| `-s` | int | `300` | min score [300] |
| `-P` | flag | `off` | print scoring |

**Positional arguments**

| Argument | Type | | Description |
| --- | --- | --- | --- |
| `input` | `seq_file` | required | <in.fa>\|<in.fq> |

**Notes**: telomere regions go to stdout as BED; the (telo_bases, input_bases) summary goes to stderr. stk_telo asserts that every character of the -m motif maps to A/C/G/T, so an invalid motif aborts the process. -P switches stdout from BED regions to the per-base P/Q scoring profile.
